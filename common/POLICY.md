# 统一 AI 协作约束

> 这里是跨 Codex 与 Claude Code 共享的规则。请按团队实际工作方式修改；方括号内容是待替换的示例。

## 工作原则

- 默认使用中文沟通；代码、命令、标识符保持其原有语言与项目惯例。
- 先检查仓库现有约定、贡献指南和相关实现，再提出或实施改动。
- 只做当前请求所需的最小改动；不要顺带重构无关代码或覆盖用户已有修改。
- 不确定需求、影响范围或有破坏性风险时，先说明假设并请求确认。

## 代码与验证

- 遵循项目已有的格式化、类型、测试和提交规范。
- 修改代码后，运行与改动相称的检查或测试；无法运行时说明原因和未验证的部分。
- 报告结果时说明：改了什么、验证了什么、仍有哪些已知限制。

## Excel 模板处理

- 批量修改 `.xlsx` 模板前，先确认使用的读写工具会保留模板的 OOXML 结构；不得仅为替换少量文本而无差别地读取并重导出整本工作簿。
- 对现有模板做定点修改时，优先仅修改目标单元格或对应的 ZIP/XML 条目，保留未涉及的工作表结构、样式、合并单元格、公式和关系文件。
- 必须保留已有工作表的 `<dimension ref="..."/>` 节点及其原始引用范围。该节点在 OOXML 中可选，但 EasyExcel 的模板写入流程可能直接访问它；节点缺失会在写入器关闭时触发空指针异常。
- 修改完成后，至少校验每个模板能正常解压，并使用实际消费它的库执行一次模板加载、写入和关闭验证；使用 EasyExcel 的项目应覆盖 `withTemplate(...).build()` 到 `ExcelWriter.close()` 的完整流程。

## 安全与数据

- 不读取、输出、提交或上传密钥、令牌、密码、私有证书和个人敏感数据。
- 不执行不可逆或大范围删除、覆盖、重置操作，除非用户明确授权且目标范围已核实。
- 对外发送消息、创建公开资源、部署或产生费用前，先取得明确授权。

## 交付方式

- 优先给出可执行的结论和下一步，而不是冗长过程描述。
- 引用本地文件时使用准确路径；解释关键取舍和用户需要决定的事项。
